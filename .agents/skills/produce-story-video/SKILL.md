# 剧情视频制作

以剧情、角色与场景连续性、完成速度共同决定制作方案。AI 负责创作、依赖分析、任务调度和内容判断；脚本执行 API 请求、任务记录、媒体处理与技术校验。

## 制作主线与扩展位置

| 制作阶段 | 核心输入与结果 |
|---|---|
| 设定、剧本与分镜（节点 0–4） | 从剧本确定人物、空间和道具。取得人物参考和每处空场景的固定布局参考。写出各镜的起止状态、对白和镜长，完成原有的一轮内容与时长检查。设定图和文字分镜可并行准备。 |
| 镜间依赖与首帧（节点 5–7） | AI 逐镜记录依赖及理由。动作结果、人物站位、物品数量、持有者或位置需要承接时，先检查来源视频并选定采用版本，再取其真实末帧，与本场空间和人物参考一起编辑下一镜首帧。按依赖并行模式下，只共享外观或明确独立的镜头在其参考就绪后可并行。逐镜串行模式额外强制每个后镜承接紧前镜实际尾帧。遗漏或不确定的判断按播放顺序保守承接前镜。 |
| 提示词、确认与视频（节点 8–11） | AI 看实际首帧和选用的目标尾帧，按 H3 格式写出表演、逐字对白和声音。用户确认当前素材后提交视频，每个新候选按既有规则检查一次。采用结果才能解锁连续后镜。 |
| 局部返工与交付（节点 12–13） | 替换候选时保留原版，沿来源记录重算受影响的后镜。按播放顺序合成所有采用片段，完整保留原生音轨。 |

合入的 `short-drama-write` 和 `short-drama-storyboard` 丰富节点 1、3–4 的冲突、对白与切镜设计，`short-drama-video-prompts` 丰富节点 8 的 H3 表演与声音写法。后续合入方法时，标明所补充的节点、输入和输出。涉及改变既定节点、依赖、模型、检查轮次或交付行为的建议，单独交用户决定。AI 直写为首次建议，最终提示词路线以用户保存的本片选择为准。付费视频提交前继续由用户确认素材。

## 开始工作

1. **首次使用先设置**。新建影片前执行 `setup`。未配置时按[首次设置与选项影响](references/first-use.md)向用户展示选择，待其确认后保存，再用 `init` 建片。工作台与对话共用这组偏好。每部新片保存独立快照，续做直接使用本片配置。读取用户材料和本次配置。从本仓库运行时，使用项目解释器调用 `scripts/media.py`，它读取安装时生成的 `config/local-settings.json`。独立调用可从 [configs/default.json](configs/default.json) 起步，按 [references/configuration.md](references/configuration.md) 配置运行路径。模型、API 地址、凭据环境变量名、路径和限额从配置读取。
2. 从上下文取得故事、时长、画幅、风格、已有素材、预算和交付位置。补充询问会改变制作方案的缺失信息；已有答案和授权继续生效。
3. 在独立项目目录保存工作。续做时读取该项目的分镜、任务、检查记录和暂停状态，以及工作台保存的 `creative-brief.json`、`workflow-inbox.json` 和 `material-approvals.json`。先处理待规划需求和修改意见，按 [references/material-review.md](references/material-review.md) 交接；用户恢复指令对应当前项目。用户明确要求改变本片路线时才更新后续设置并记录变更。
4. 执行一次 `doctor`，每种模型配置首次使用时取得一次接口规格。通过 [references/operations.md](references/operations.md) 调用原子操作；依赖的模块位于配置指定的 `video-harness`。
5. 工作台的“开始生成”和“继续生成”驱动同一后台队列，沿用本版授权和已有任务。暂停后同步已受理的片段。AI 接手续做时先读取队列状态，已由后台接管的任务交给该队列提交和下载。

## 由 AI 推进制作

- 按 [references/workflow.md](references/workflow.md) 的节点输入与输出推进：人物/场景设定与剧本、分镜 → 内容检查 → 依赖队列 → 首尾帧 → 所选帧检查 → 按本片路线准备提交正文 → 所选 Prompt 检查 → 用户在工作台确认素材 → 视频 → 视频检查 → 合成。
- 视频提交前，先备齐实际请求与图片，打开本地工作台供用户查看首帧、目标尾帧、对白、时长和最终提示词。默认 `review.require_material_approval: true`；当前版本未经用户确认时停在这里，不能替用户点击确认、伪造记录或为继续生成关闭此设置。用户可逐段确认或批量确认，也可留下修改意见。素材、提示词、时长、画幅或模型参数变化后须重新确认；有依赖的后镜待实际素材就绪后再确认。用户确认不解除暂停，也不代表预算授权，不增加 VLM、ASR 或音频检查；详见素材确认文档。
- 创作或修改故事时读取 [references/story-writing.md](references/story-writing.md)：先写人物想达成什么、遇到什么阻力、采取什么行动及其后果，再写完整场景剧本与有作用的对白。用户已确定的剧情与台词按授权范围保留，不能借整合创作方法擅自重写。
- 拆分镜头时读取 [references/scene-planning.md](references/scene-planning.md)：先安排整场戏的动作、对白、反应和必要声音，再按信息变化与切镜理由形成可生成的镜头。写作和整场时间安排均属于原有创作节点，不增加模型调用、审阅轮次或确认关卡。
- H3 普通中文对白以 **4.1 个实读汉字/秒**估计净说话时长，再加有依据的起声、停顿和换人时间，与可同时发生的动作重叠；最后一句后保留 **0.8–1 秒**。按当前接口取最短合法时长，不先定统一镜长再填表演。合并短反应，过密时在完整句子和自然动作边界切分；同一生成片段内可按 H3 官方格式安排少量有信息变化的切镜，避免把每句台词拆成独立请求。估时公式、动作容纳和切分边界见整场规划文档。
- 用户给出的“以内/不超过”写入 `production.max_duration_ms`；`target_duration_ms` 只记录各镜请求时长之和。规划为模型返回的额外片尾留出空间；完整素材超出用户上限时调整分镜，不能硬切声音。既有的一次内容/时长检查同时处理节奏与句尾余量。
- 首帧描述动作前状态。目标尾帧由 AI 为本镜的关键结束状态按需选用。下一镜继承的是采用视频完整画面的实际末帧。换机位或切到人物反应时，仍须判断桌面、道具和人物关系是否承接。逐镜依赖与记录示例见[工作流](references/workflow.md#并行队列)。
- 读取 `production.scheduling`。**逐镜串行**按播放顺序一次制作 1 段，后镜的首帧必须绑定前镜已检查采用的实际尾帧。即使分镜写成 independent/high，仍须等待。**按依赖并行**只放行就绪镜头，默认最多 4 段视频。两种模式都保留跨镜道具和非相邻来源，图片与编辑默认最多 2 个，总媒体最多 6 个。
- 生成视频提示词前读取 [references/video-prompts.md](references/video-prompts.md) 与 [references/minimax-h3.md](references/minimax-h3.md)。按上游 `short-drama-video-prompts` 的“输入/模式 → 时长容纳 → 动作、表演、运镜、声音”方法，由当前 AI 对照实际素材写稿。读取 `rewriter.mode`。直写原文提交，本地改写使用真实首尾帧及改写记录，在线优化只在视频请求启用服务端增强。每次只用一种。H3 的直写和本地路线显式关闭服务端增强。其他兼容模型使用对应接口的提示词规范。
- 人物表演写出触发原因、具体情绪、景别可见的表情/身体变化、对白重音和节奏、听者回应及结束状态。关键情绪应随行动变化，避免全片统一“平静地说”、无依据的喊叫或慢推。稳定的说话人编号和音色描述跨镜复用，情绪语气随情节变化；逐字对白只在指定标签中出现一次。
- 在剧本和分镜中写明台词原文、说话人、语气、环境声和动作音效，由视频模型与画面一起生成，默认使用原生音轨。不接入额外配音、音效服务，也不因有对白增加检查节点或次数。用户需要字幕时，依据实际音频转写并对齐；预写对白保留为字幕草稿。
- 抽样、取实际尾帧及合成使用完整源视频；请求时长不能作为成片裁切点。合成保留完整原生音轨，声音长于画面时仅延续最后一帧，不加速、不截音、不叠压相邻对白。旧候选沿用已有检查记录，不补声音检查。

## 检查次数与返工次数

以下为推荐初始值。按本片保存的首尾帧检查、Prompt 检查、视觉执行者和返工额度执行。AI 记录检查次数与每镜返工次数，脚本执行抽帧、技术校验和视频返工上限。

| 检查 | 次数与范围 |
|---|---|
| 剧情与分镜时长 | 每版分镜 **1 次**，输出修正后的可执行分镜 |
| 首尾帧 VLM | AI 按需选择；普通镜头 **0 次**，启用后每组候选 **1 次**，首尾帧合并查看 |
| Prompt 一致性 | AI 按需选择；普通镜头 **0 次**，启用后每份最终提示词候选 **1 次** |
| 视频内容 | 每个新视频候选 **1 次**；均匀抽取 **6 帧**，包含实际保留片段的首帧和末帧，每帧最长边 **512 px** |
| 内容返工 | 每镜各内容节点共享 **1 次**；替换候选在对应节点再检查 **1 次**，相同输入和候选复用结论 |

视频检查同时关注人物/场景、主要动作、关键物品和结束状态；能听取原生音轨时，在同一轮记录声音检查。当前 AI 与配置的视觉 API 二选一完成该轮，报告记录实际采样时间点和音频覆盖。

`pass` 继续。`uncertain` 或轻微瑕疵记录后继续。`serious` 记录时间点或图片位置、观察事实和修正方向。默认每镜可返工一次。用户已明确允许本版追加返工时，将授权与本版项目、积分上限绑定，每次对最新的严重问题候选返工并记录。新增素材或更改提示词仍需用户确认。

脚本在新请求时校验参数、引用与输入绑定，在下载后校验媒体，在合成时校验时间线、时长和音轨。检查清单、采样公式和分支去向见工作流文档。

## 重要决定与交付

剧情/角色/目标时长、服务方或付费模型、预算/返工次数、交付规格和改写方式的新增变更由用户决定。AI 按已选调度方式组织镜头，决定按需目标尾帧和按需检查，在本片已选的 0 或 1 次返工额度内处理。

交付成片及绝对路径、剧本/分镜、采用镜头与原候选、有效配置、检查记录和耗时。总耗时按开始至结束的墙钟时间计算，环节耗时、调用数、返工数和费用单列。交付状态标明完成内容及待处理项目。

查阅工作流来源和历史检查设置时，读取 [references/provenance.md](references/provenance.md)。
