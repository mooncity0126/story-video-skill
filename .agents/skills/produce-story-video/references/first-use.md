# 工作流首次设置

从仓库根目录使用已安装的 Python 运行 `scripts/media.py setup`。它会列出每个选项、影响、建议值及是否已确认。工作台右上角的「工作流设置」读取同一份数据，直达地址为 `http://127.0.0.1:8787/?setup=1`。

- 首次使用时，让用户看到选择及代价。可一次确认整组设置或调整个别项。允许先关闭去查看已有影片。推荐值只有用户确认保存后才生效。
- 在对话中操作时，展示本页主要选择及可展开的创作、检查、返工选项，等待明确答复。以 `setup` 返回的 `values` 为底，合入用户选择，把完整的键值对象写入临时 UTF-8 JSON，用同一入口执行 `scripts/media.py setup --answers <文件>`，再执行 `scripts/media.py init --output <新片目录>`。
- 本机网页与不同的 harness 须让安装模板的 `workflow_preferences_file` 指向同一文件。新片创建时保存独立的 `settings.json`。续做直接读那部片的快照。旧快照缺少调度方式时沿用原有的按依赖调度。
- 创作、设定图和视频的积分按片授权。安装偏好没有积分上限，保存操作不提交任务。各项可选检查由执行本 skill 的 AI 按快照在原节点落实并记录，后台队列处理素材、提交及等待状态。

| 设置 | 用户选项与影响 |
|---|---|
| 视频调度 | 推荐逐镜串行。后一镜须等播放顺序中的前镜完成、检查、采用并取得实际尾帧，跨镜动作、道具和人物较容易延续。按依赖并行能缩短独立分镜的等待，镜间承接仍需正确标注。换场景或机位时可基于尾帧和新场景参考编辑下一镜的构图。两种方式都保留非相邻来源依赖，人物与场景设定图仍可并行准备。 |
| 视频模型 API | 填兼容 LightX2V Cloud 的 HTTPS 地址、模型标识、阶段和密钥名称，默认使用当前配置的 MiniMax-H3。视频输入会发往该地址。模型影响原生声音、合法镜长、参考图支持和报价。本工作流选用支持首帧与原生声音的 `i2av` 模型，规格和报价在制作时核对。修改视频 API 只作用于视频角色。 |
| 提示词处理 | 三选一。直写原样送出当前 AI 对照真实素材完成的正文。本地改写用兼容权重处理实际图像和原稿，占用本机算力，提交前能检查改写结果。在线优化将原文和素材随视频请求送到服务端，可能调整对白和情绪用词，确认时只能看见将要发出的原文。 |
| 剧本与设定 | 当前 AI 执笔，或让已配置的外部文字模型参与节点 1、3。后者发送对应文字并使用其额度，最终视频提示词仍按单独的提示词选择处理。用户已有定稿照原授权使用。 |
| 首尾帧、提示词一致性 | 两处分别选按需、总是或关闭。按需只在疑点出现时检查，总是会增加候选准备时间，关闭由用户素材确认承接可见问题。启用后每个对应候选仍只检查一次。 |
| 画面检查执行者 | 当前 AI 或配置的外部视觉 API。后者会发送检查所需的画面并可能计费。视频候选都沿用原有的一轮检查。 |
| 严重问题返工 | 每镜可选 0 或 1 次。0 表示记录问题并等待用户处理，1 表示可以在本片额度内返工一次。保留原候选与上下游引用。 |

## 每部影片和每一镜另行决定

每片单独记录创意或已有剧本、片长上限、画幅、风格、已有图片、字幕需求、交付位置和预算。已有设定图可复用，需要时才生成或编辑。目标尾帧在关键结束状态需要约束时选用，多一张图会增加准备时间和可能的积分，不能代替后镜需要的实际视频尾帧。原生对白与音效、句尾余量、生成前用户确认、每个新视频候选一次内容检查、合成保留完整原生音轨均继续执行。

## 在原节点记录选定检查

读取本片 `production.writer`，在节点 1、3 使用当前 AI 或配置的 `text` 服务。节点 7、9 分别读取 `review.frame_check`、`review.prompt_check`。按需时在每镜 `checks.frame.enabled` 和 `checks.prompt.enabled` 记录决定及理由。选择外部视觉 API 时，将本轮所需画面交给已配置的 `vision` 服务，在同一轮使用返回的判断。

首尾帧就绪后，先用 `--run <片目录> check-inputs --shot <镜号>` 获取本轮画面检查指纹。完成已选的画面检查后再准备最终提示词。对准备提交的视频请求运行 `--run <片目录> check-inputs --request <请求文件>`，得到该候选所需的检查及各自输入指纹。使用本轮已有观察，在 `checks/<镜号>-frame.json` 或 `checks/<镜号>-prompt.json` 保存对应的 `source_hashes`、`enabled: true`、`round: 1`、`outcome` 及 `evidence`。相同候选沿用有效记录。队列等待已选择且实际需要的结论，不再额外调用模型。设置为关闭时该项没有所需记录。视频候选的正式检查仍按工作流节点 11 进行。

## 凭据与兼容性

工作台只填写密钥名称。现有名称在原 `api-keys.local.json` 中取值。新增独立服务时使用专属名称，例如 `ALT_VIDEO_KEY`，在同目录 `ALT_VIDEO_KEY.local.json` 写入 `{"ALT_VIDEO_KEY":"你的密钥"}`。密钥不进入工作台偏好或影片快照。在线优化依赖接口明确提供布尔型 `enhance_prompt`，不支持时会在报价或提交前提示。直写和本地改写在 H3 显式发送 `false`，在线模式发送 `true`。通用文字 API 或单纯更换模型名称不能替代兼容的视频网关。
